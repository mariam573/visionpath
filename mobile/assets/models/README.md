# Mobile model assets

The app decoder is currently wired for the pinned seven-class order, `float32` RGB NHWC 640×640 input, and one float32 end-to-end `[1, N, 6]` output (`xyxy, confidence, class id`). This is a provisional runtime contract, not a selected model. No model is included because the repository has no versioned training dataset, reviewed weight/data license, exported checkpoint, or real-device benchmark. The app stays in preview-only mode until those gates pass.

Follow `ai-models/model-selection-protocol.md`, create a completed copy of `ai-models/mobile-validation.example.json`, and run `python ai-models/package_mobile_model.py --model <candidate.tflite> --validation-report <report.json>`. The fail-closed packager verifies the shared candidate comparison, reviewed redistribution rights, per-class and key-finding results, real-device latency/memory/thermal/battery logs, native runtime/delegate compatibility, measured export parity, float32/quantized comparison, dependency-lock checksums, selected thresholds and rollback evidence. It copies the model here and activates its Metro asset reference only after all checks pass. The model runs locally; no model download or network call is part of assistance.
